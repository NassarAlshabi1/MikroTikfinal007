# تقرير إصلاح شاشة إنشاء كروت Hotspot الجماعية

## المشكلة

كانت شاشة إنشاء الكروت الجماعية تعتمد على `RootIsolateToken` وتهيئة `BackgroundIsolateBinaryMessenger` داخل Isolate، ثم تستدعي `MikrotikConnector.connect()` من داخل العزل. هذا المسار يخلط بين منطق الشبكة ومنطق Flutter Plugins مثل `SharedPreferences` و`flutter_secure_storage`، وقد يؤدي إلى توقف العملية أو ظهور الشاشة وكأنها لا تعمل، خصوصاً على بعض المنصات أو بعد تغير دورة الاتصال.

كما أن HomeScreen قد يفتح BulkAddScreen بقائمة profiles فارغة إذا فشل التحميل الأول أو حدث بالتوازي مع تحديث لوحة الحالة. عندها كانت شاشة الإنشاء تعرض قائمة فئة فارغة دون تحميل ذاتي أو زر تحديث واضح.

## الإصلاحات

| المجال | التغيير |
|---|---|
| Isolate | إزالة `RootIsolateToken` و`BackgroundIsolateBinaryMessenger` من مسار إنشاء الكروت. |
| الاتصال | إضافة `MikrotikConnectionConfig` و`loadConnectionConfig()` لقراءة الاعتمادات على UI isolate فقط. |
| RouterOS | إضافة `connectWithConfig()` لإنشاء اتصال مستقل داخل Isolate باستخدام إعدادات جاهزة، مع إغلاق العميل عند فشل تسجيل الدخول أو المهلة. |
| profiles | إضافة تحميل مباشر لبروفايلات `/ip/hotspot/user/profile/print` عند فتح الشاشة إذا كانت القائمة فارغة، مع زر تحديث وحالة تحميل ورسالة واضحة. |
| البيانات | تطبيع أسماء البروفايلات وإزالة القيم الفارغة والمكررة لمنع أخطاء DropdownButton. |
| الأخطاء | أصبحت أخطاء الاعتمادات والاتصال تمر عبر مسار واضح بدلاً من توقف صامت أو عملية غير مستجيبة. |
| الاختبارات | تحديث BulkAddIsolateData tests وإضافة تغطية لحالة عدم توفر profiles أو استمرار تحميلها. |

## مسار التشغيل بعد الإصلاح

تقرأ الشاشة إعدادات MikroTik والاعتمادات على UI isolate، ثم تمرر كائناً مستقلاً لا يحتوي على Flutter Plugin إلى Isolate. ينشئ العزل اتصال RouterOS v6 عبر Binary API، ويضيف المستخدمين باستخدام `/ip/hotspot/user/add` وحقول `name`, `password`, و`profile`. بعد الإضافة الناجحة يعيد النتائج إلى الشاشة، ثم تُحفظ الكروت محلياً في Isar وتظهر خيارات العرض والمشاركة والتصدير.
