# مراجعة مشاريع GitHub المنافسة التي تعمل على Android

**تاريخ المراجعة:** 2 أكتوبر 2026

**النطاق:** تطبيقات Android أصلية أو مشاريع Flutter لها هدف Android، وتتعامل مع MikroTik/RouterOS أو Hotspot والكروت. استُبعدت تطبيقات الويب/سطح المكتب البحتة، حتى لو أمكن فتحها على Android.

## الخلاصة التنفيذية

- **WireSpot** هو أقرب منافس Android مباشر لمسار الكروت: دفعات vouchers وQR وطباعة Bluetooth حرارية وتقارير مبيعات وعدة راوترات. يوجد نجاح CI فعلي لبناء APK، لكن ذلك لا يثبت نجاحه على راوتر أو طابعة حقيقية. كما أن المستودع **ذو ترخيص احتكاري**؛ يصلح لمقارنة الأفكار فقط، لا لنسخ الشيفرة أو القوالب.
- **RootMikroManager** يعلن مجموعة Hotspot واسعة ويحتوي ملفات Dart فعلية لوحدات Hotspot/vouchers، لكنه لا يملك إصدار Android منشوراً، ووثائقه تؤجل التحقق النهائي من بناء APK واختبار الجهاز الحقيقي. لا يظهر ترخيص محدد.
- **Mikrotik-flutter-app** مرجع صغير للعربية/الإنجليزية ومسارات Hotspot، لكنه مؤرشف، ولا توجد نسخة منشورة، ويستخدم REST عبر HTTP في الشيفرة؛ لذلك ليس مناسباً مباشرةً لراوتر RouterOS v6.49.19.
- **Androtik** تطبيق Kotlin/Jetpack Compose أصلي لإدارة الشبكة، لا لإنتاج الكروت؛ Hotspot ما يزال بنداً في خارطة الطريق.
- بالمقارنة، مشروعنا لديه بالفعل إنشاء جماعي مع حفظ الدفعات والتعامل مع الفشل الجزئي، وقوالب PDF مخصصة. الفجوات الأوضح التي تستحق التقييم هي QR، والطباعة الحرارية، وسجل مبيعات فعلي، وإدارة عدة راوترات. لكن **يجب أولاً حسم تعارض Hotspot مقابل User Manager في المسار الافتراضي**.

## منهج وحدود الثقة

راجعت README وبيانات المستودع، وبنية الشيفرة والاختبارات أو CI عندما كانت متاحة. أميز هنا بين: «يعلنه README»، و«توجد له ملفات تنفيذ في المستودع»، و«نجح بناء CI». لم أشغّل هذه التطبيقات على هاتف Android، ولم أربطها براوتر أو طابعة فعلية؛ لذلك لا أصف نجاح CI بأنه اختبار ميداني أو إثبات لصحة أوامر RouterOS.

## المشاريع الأقرب

### 1. WireSpot — أقرب منافس مباشر للكروت

- **المنصة والاتصال:** Flutter لتطبيق Android/iOS، مع عميل RouterOS API داخل التطبيق؛ وطبقات Kotlin على Android لبعض وظائف VPN وBluetooth والطباعة.
- **ميزات الكروت المعلنة:** إنشاء فردي/دفعات، صيغ username/password أو username فقط أو PIN، بادئة ومجموعة محارف وأطوال، حدود بيانات وسعر، QR، معاينة قسيمة، قوالب 58/80 مم، وطباعة ESC/POS عبر Bluetooth.
- **ميزات التشغيل التجاري:** تقارير مبيعات وتصدير، اختيار عدة راوترات واختبار الاتصال بها، نسخ احتياطي وجدولة بعض المهام، ودعم WireGuard للاتصال البعيد.
- **ما أمكن التحقق منه:** توجد ملفات Flutter وworkflow يفحص التنسيق والتحليل ويشغل الاختبارات ويبني APK للإصدار. أحدث تشغيل GitHub Actions الذي راجعته (28 سبتمبر 2026) انتهى بنجاح وأنتج artifact لـAPK بحجم 44.6 MB. يذكر README أيضاً 82 اختباراً ناجحاً.
- **ما لم يُتحقق منه:** لا يثبت CI عمل voucher creation أو Bluetooth أو WireGuard على راوتر/هاتف فعلي؛ README نفسه يذكر أن مزيداً من الاختبار الميداني مطلوب.
- **تحذيرات:** ملف LICENSE يعرّف البرنامج بأنه احتكاري، وكل الحقوق محفوظة. كذلك يوجد تناقض داخل README: ملخص الحالة يقول إن ستة موصلات نشطة بالكامل، بينما جدول دعم العلامات يصف MikroTik فقط بأنه كامل، وRuijie/Reyee محدوداً، والباقي مخططاً. لذلك أتعامل مع MikroTik كالموصل المدعوم وحده، ولا أعتبر بقية العلامات ميزات مكتملة.

روابط: [المستودع](https://github.com/Uszkido/wirespot) · [تشغيل CI الناجح](https://github.com/Uszkido/wirespot/actions/runs/36401119633) · [ملف الترخيص](https://raw.githubusercontent.com/Uszkido/wirespot/main/LICENSE) · [workflow](https://raw.githubusercontent.com/Uszkido/wirespot/main/.github/workflows/ci.yml)

### 2. RootMikroManager — أوسع Flutter لإدارة RouterOS، لكن Android غير مثبت ميدانياً

- **المنصة والاتصال:** Flutter متعدد المنصات وله مجلد Android، ويتحدث مباشرة مع الراوتر عبر RouterOS API/API-SSL وREST HTTPS، من دون خادم PHP وسيط حسب README.
- **ميزات Hotspot المعلنة والموجودة لها ملفات مصدر:** المستخدمون والجلسات والبروفايلات، وإنشاء vouchers مع الأنماط والبادئات والأطوال وحدود الوقت/البيانات، وسجل محلي، QR وPDF/طباعة. توجد مجلدات Dart فعلية لـHotspot وvouchers، وليس README فقط.
- **ميزات إضافية:** مجموعة راوترات مع مجموعات/وسوم، اكتشاف شبكة وVPN/RoMON، تقارير، نسخ احتياطي، مراقبة، وميزات شبكات عامة.
- **حالة التحقق:** README يحذر من وجوب اختبار الوحدات على أجهزة RouterOS حقيقية قبل الإنتاج. لا توجد إصدارات منشورة في صفحة Releases التي راجعتها. وثائق البناء تطلب تشغيل بناء Android محلياً، وملف Android build يصرح بأن البناء النهائي يجب تنفيذه في بيئة Flutter/Android؛ كما أن تدقيق الاكتمال يضع مرحلة APK/release ضمن العمل المؤجل.
- **تحذيرات:** لا يظهر ترخيص محدد في بيانات GitHub؛ لا تنسخ الشيفرة قبل حسم الترخيص. كما أن وثائق المشروع سجل مراحل طويل، ولذلك لا أعدّ كل بند موصوفاً بأنه «مغلق» دليلاً على اختبار ميداني.

روابط: [المستودع](https://github.com/aesoltec/RootMikroManager) · [README](https://raw.githubusercontent.com/aesoltec/RootMikroManager/main/README.md) · [تدقيق الاكتمال](https://raw.githubusercontent.com/aesoltec/RootMikroManager/main/docs/COMPLETENESS_AUDIT.md) · [تعليمات بناء Android](https://raw.githubusercontent.com/aesoltec/RootMikroManager/main/android/README_ANDROID_BUILD.md) · [الإصدارات](https://github.com/aesoltec/RootMikroManager/releases)

### 3. Mikrotik-flutter-app — مرجع عربي تاريخي، لا يصلح كمسار RouterOS v6

- **المنصة والميزات المعلنة:** Flutter مع هدف Android؛ إدارة Hotspot users/plans/vouchers، ولوحة معلومات، وتوطين عربي/إنجليزي. توجد ملفات تنفيذ للطباعة وخدمة RouterOS، لكن لا يوجد إصدار Android منشور راجعته.
- **الحالة:** المستودع مؤرشف في GitHub، وآخر دفع ظاهر 2 أبريل 2026؛ README يذكر الترخيص لكن GitHub لا يتعرف على ترخيص محدد ولا يظهر ملف `LICENSE` المعتاد.
- **قيد توافق مهم:** `routerboardservice.dart` يستخدم `http://<router>:<port>/rest` مع Basic Authentication، ويستعمل أيضاً backend خارجي لبعض العمليات. توثيق MikroTik يقول إن REST API بدأ في RouterOS v7.1beta4؛ لذلك هذا المسار لا يطابق RouterOS v6.49.19. كما لا توصي MikroTik باستخدام REST عبر HTTP في الإنتاج لأن بيانات الاعتماد قد تُلتقط على الشبكة.
- **التقييم:** استلهام شكل العربية/RTL فقط؛ لا أوصي بالاعتماد عليه أو نسخ شيفرته قبل مراجعة الترخيص والأمان.

روابط: [المستودع](https://github.com/amolood/Mikrotik-flutter-app) · [README](https://raw.githubusercontent.com/amolood/Mikrotik-flutter-app/master/README.md) · [خدمة الراوتر في الشيفرة](https://raw.githubusercontent.com/amolood/Mikrotik-flutter-app/master/lib/utility/routerboardservice.dart) · [توثيق MikroTik الرسمي لـREST](https://help.mikrotik.com/docs/spaces/ROS/pages/47579162/REST+API)

### 4. Androtik — Android أصلي لإدارة الشبكة، وليس منافس كروت حالياً

- **المنصة:** Kotlin وJetpack Compose، وتطبيق Android أصلي يتصل عبر RouterOS API/API-SSL.
- **ما يعرضه README كمنفذ/أساسي:** ملفات تعريف لعدة راوترات، معلومات النظام، الواجهات، IP/routes، DHCP leases، وعرض قواعد Firewall.
- **ما لا يقدمه حالياً حسب خارطة الطريق:** Hotspot active users/hosts نفسها ما تزال TODO؛ لا توجد ميزة vouchers أو بيع/طباعة كروت ضمن المنفذ الحالي المعلن.
- **التقييم:** مرجع لواجهة Android الأصلية، وإدارة الجلسة والراوترات، لا لتوسعة مسار الكروت. المشروع يصف نفسه بأنه قيد التطوير. ترخيصه Apache-2.0.

روابط: [المستودع وخارطة الطريق](https://github.com/dulumina/androtik) · [الترخيص](https://github.com/dulumina/androtik/blob/main/LICENSE)

## أمثلة حدودية استُبعدت من المنافسة المباشرة

- **vouchermkt:** مشروع LiveCode قديم يذكر إمكانية إخراج Android، لكنه لا ينشر APK/Release في GitHub، وآخر تعديل للمصدر يعود إلى 2015. يتعامل عبر SSH مع User Manager، ويولّد أرقاماً عشوائية ويتحقق من عدم تكرارها ويطبع القسائم؛ يصلح كمرجع تاريخي لمسار User Manager فقط، لا كتطبيق Android منافس حديث.
- **FG-MikroTik-Manager:** مشروع Android/Kotlin حديث النشر، لكن صفحة المستودع كانت تحتوي README تأسيسياً فقط بلا شيفرة تطبيق؛ استُبعد لأنه خطة لا تنفيذ.
- **WavePass-Android:** ظهر في نتائج البحث كـFlutter POS، لكن رابط GitHub أعاد 404 عند التحقق في تاريخ المراجعة؛ لم أحتسب مزاياه كدليل.
- **Mikhmon وما شابهه:** حتى إن أمكن تشغيله على Android بواسطة web server محلي ومتصفح، فهو تطبيق ويب لا Android native/Flutter، ولذلك خارج النطاق الذي طلبه المستخدم.
- مكتبات RouterOS API وحدها ليست منافساً لتطبيق إدارة كروت.

## نقطة P0 في الشيفرة الحالية

وجدت تعارضاً يجب حسمه قبل أي إضافة للكروت:

- `lib/features/dashboard/presentation/home_screen.dart:268` يعرّف `_serviceMode` ثابتاً على `MikrotikServiceMode.userManager`.
- `lib/bulk_add_screen.dart:44` يستخدم User Manager افتراضياً أيضاً عند عدم تمرير نمط.
- `lib/services/mikrotik_card_commands.dart` يوجّه Hotspot إلى `/ip/hotspot/user/add`، وUser Manager إلى `/tool/user-manager/user/add`.
- بالمقابل، `docs/ROUTEROS_V6_HOTSPOT_REVIEW.md` و`docs/BULK_HOTSPOT_ISAR_FIX_REPORT.md` تصف Hotspot المحلي في RouterOS v6 بأنه الوضع الافتراضي.

هذا تعارض في الشيفرة/الوثائق، وليس حكماً على نجاح التشغيل على جهاز فعلي. يلزم اختبار أمر الإنشاء مع نمطي الخدمة كل على حدة، ثم تجربة كرت واحد ودفعة صغيرة على RouterOS 6.49.19 قبل اعتبار المسار صحيحاً.

## مسار تنفيذ آمن إذا وافق المستخدم على الميزات

1. إصلاح/حسم نمط الخدمة أولاً، وإضافة اختبارات على command builder تثبت أن Hotspot لا يرسل أوامر User Manager والعكس.
2. اختبار Android وراوتر حقيقي مع بروفايل واحد، ثم دفعة صغيرة، وفشل اتصال جزئي، ثم الاستئناف والتحقق من Isar.
3. إضافة QR وESC/POS كطبقة تصدير/طباعة فوق الكروت الحالية، مع عدم حذف قوالب PDF أو تغيير بيانات الكروت القديمة.
4. عند إضافة الأسعار أو المبيعات أو عدة راوترات، استخدام ترحيل قاعدة بيانات إضافي مع قيمة واضحة للسجلات القديمة، والإبقاء على سجلات الوظائف والحجوزات وحالات الفشل والاستئناف.
5. لا تُنسخ شيفرة أو تصميمات من WireSpot أو RootMikroManager قبل حل الترخيص؛ ويمكن تنفيذ الأفكار العامة بتنفيذ أصلي.

**لم تُجرَ تغييرات برمجية على التطبيق بناءً على هذه المقارنة.** هذا الملف تقرير وتوصيات فقط.
