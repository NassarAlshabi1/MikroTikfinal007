# Isar Migration Refactor — Engineering Review

## Applied fixes

### Database / migration
- Removed the obsolete `build.yaml` Drift generator configuration.
- Made startup migration single-flight so concurrent startup paths cannot run the same migration twice.
- Kept migration version advancement after all migration stages succeed.
- Made saved-card migration atomic per source file: profile creation and card insertion occur in one Isar transaction.
- Added in-memory duplicate protection for repeated diagnostic snapshots in the same legacy payload.
- Hardened legacy JSON parsing against non-string dynamic values.

### Synchronization
- RouterOS transport failures are no longer converted into an empty successful response. Errors now propagate to `SyncResult.success == false`.
- Removed fabricated `lastUsedAt` timestamps during synchronization.
- Removed fabricated `lastUsedAt` timestamps when generated cards are merely activated.
- Added parsing/storage of User Manager profile uptime limits when RouterOS returns them.
- Made the fallback profile deterministic (`__unassigned__`) instead of attaching cards to an arbitrary first profile.
- Improved disabled-state parsing for RouterOS boolean-like values (`true`, `yes`, `1`).

### Profile integrity
- Explicit profile deletion now cascades to dependent cards, preventing dangling `profileId` references.
- Profile synchronization is now upsert-only; a partial/empty RouterOS response cannot silently delete local profiles and orphan cards.
- Hardened RouterOS profile parsing for dynamic response types.

### CI / build system
- Replaced all Drift-specific code-generation steps with the generic Isar `build_runner` generation step.
- Removed obsolete Drift/SQLite CI setup and comments.
- Removed the obsolete Drift analyzer exclusion.
- CI analysis is now blocking where it was previously explicitly ignored.
- Code-quality CI no longer mutates the repository by auto-committing formatter changes; it fails on formatting drift instead.
- Web CI remains explicitly skipped pending a separate validation of the current Isar/Web/plugin matrix; no unsupported claim is made about Drift/SQLite.

### Regression coverage
Added `test/database/isar_regression_test.dart` covering:
- Dynamic RouterOS profile parsing and duration conversion.
- Profile deletion cascading to dependent cards.
- Preservation of `lastUsedAt` during card activation.
- Upsert-only profile synchronization.

## Remaining architectural note

The old lockfile contained `drift`/`sqlite3` because `dio_cache_interceptor_db_store` was still selected. That cache backend has now been replaced by `http_cache_isar_store`, and the lockfile was intentionally removed so `flutter pub get` can resolve a clean dependency graph.


## Second-pass deep migration fixes

- Replaced `dio_cache_interceptor_db_store` (Drift/SQLite) with `http_cache_isar_store`, so the HTTP cache no longer introduces Drift transitively.
- Removed the stale `pubspec.lock` from this patch because it must be regenerated by `flutter pub get` after the dependency graph change.
- Bumped the application migration version to 2 and added referential-integrity repair for orphan cards.
- Legacy saved-card source files are deleted only after a successful Isar transaction.
- Removed nested Isar write-transaction behavior from sync fallback-profile creation.
- Added a stable `__unassigned__` profile for RouterOS users whose profile cannot be resolved locally.
- Removed the misleading `maxAge` parameter from the Dio cache helper; cache freshness follows HTTP directives, while `maxStale` controls stale fallback.
- Added concurrency protection and explicit close support for the cache store.
